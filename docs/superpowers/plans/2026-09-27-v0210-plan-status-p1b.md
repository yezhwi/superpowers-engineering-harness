# v0.2.10 Plan Status P1B Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add read-only `harness plan status` text and JSON reports backed by exactly the existing P0 reconciliation semantics.

**Architecture:** Refactor P0 final validation so already-loaded `plan` and `execution` documents feed one document-consuming validator while the existing Gate-facing wrapper remains responsible for loading. Build one pure status report from those same documents, P0 blockers, and `plan_context_summary()`, then add thin control-plane orchestration and CLI rendering.

**Tech Stack:** Python 3.11+, argparse, PyYAML, pytest, existing Harness schemas and reconciliation modules

**Spec:** `docs/superpowers/specs/2026-09-27-v0210-plan-status-p1b-design.md`

## Global Constraints

- Implement P1B only; do not add P1C Q3 task-level checks.
- `None` means confirmed canonical artifact absence; do not introduce a missing/not-loaded sentinel.
- Disabled and FAST/Q1 paths return before any plan artifact or plan-owned proof read.
- Missing, stale, proof, disposition, and unreconciled states exit 0 as report data; malformed present sources exit 2 with `INVALID_HARNESS_STATE:`.
- Repository discovery failure remains exit 1 with `ERROR:`.
- `next_plan_item` and `final_status` must come directly from `plan_context_summary()`.
- Status blockers must preserve current P0 values, order, and early returns exactly.
- No plan/execution bodies, references, evidence payloads, reasons, Decisions, or surfaces enter output.
- Command is read-only and persists nothing.
- Run focused related tests only; never run full repository suite.
- Every commit requires explicit user authorization.

## Review Focus

- A FAST task with ad hoc `enabled: true` beside malformed artifacts must still return disabled without reading them; pinned in Task 3.
- Stale, missing, or mismatched execution must never produce apparently current progress; all trust cases are pinned in Tasks 2 and 3.
- Early-return cases must not accumulate later proof blockers; missing, stale, unknown-key, and supersession cases are pinned in Task 1.
- A terminal `COMPLETE` item with failed proof must count as reconciled while final status remains blocked; pinned in Task 2.
- Human rendering must handle unsourced blockers and passing output without an empty `Blockers:` section; pinned in Task 3.
